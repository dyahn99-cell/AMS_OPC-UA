# SMC EXW1 · IO-Link 대시보드 개발 현황 및 검수 요청서

- 작성일: 2026-10-19
- 대상: EXW1 무선 베이스·리모트 및 IO-Link 디바이스 통합 대시보드
- 목적: 지금까지의 요구사항, 구현 내용, 검증 범위와 미완료 사항을 외부 검토자가 파악하기 위한 인계 문서
- 자료 기준: 현재 작업 폴더의 소스 및 2026-10-14까지의 주요 구현·검증 기록, 이후 대화에서 합의한 개선 방향
- 문서 작성 시점에 실장비 통신 및 전체 테스트를 새로 실행하지 않았다. 아래 테스트 결과는 기존 작업 기록이다.

## 1. 현재 상태에 대한 판단

현재는 **통신·매핑·공용 위젯·설정 편집·출력 시험의 기반을 구현한 로컬 프로토타입**이다. 실제 사용자에게 제공할 상품 수준의 UI/UX와 전체 제품의 실기 검증은 진행 중이다.

제품 정의를 바탕으로 여러 제품에 같은 위젯을 적용하는 구조는 마련했다. 다만 IODD를 분석하고 화면이 생성된다는 사실만으로 모든 제품의 물리량 변환, 진단 의미, 설정 쓰기 및 장비 동작이 검증된 것은 아니다.

사용자의 최근 평가도 “기능 확인용 화면에서 상품 수준의 경험으로 발전해야 한다”는 것이다. 색상과 대비는 개선했지만 첫 화면의 정보 우선순위와 탐색 직관성에는 추가 작업이 필요하다.

## 2. 만들고자 하는 제품

하나의 대시보드에서 다음 흐름을 제공한다.

```text
PC 대시보드
  └─ Modbus TCP → EXW1 베이스
       └─ 무선 등록 채널
            ├─ 디지털 입력 / 출력 / 입출력 리모트
            ├─ 아날로그 입력 리모트
            ├─ 밸브 출력 리모트
            └─ IO-Link 마스터 리모트
                 └─ 논리 포트 → 선택한 IODD 제품
                      ├─ PD 측정값·상태
                      ├─ 사용자 선택 ISDU 조회값
                      ├─ 지원 설정값 편집
                      └─ 지원 PD OUT 조작
```

핵심 원칙은 다음과 같다.

1. 장비에서 정보를 읽지 못해도 채널, 제품, 할당 바이트를 수동으로 구성할 수 있어야 한다.
2. 채널마다 실제 등록된 리모트 종류를 선택한다. 모든 채널을 IO-Link로 가정하지 않는다.
3. 다음 채널·포트의 위치는 실제 제품의 PD 길이가 아니라 **할당 바이트**를 따라 계산한다.
4. 제품 정의와 연결 위치를 분리한다. 같은 제품도 CH1/P1과 CH2/P2에서 독립적으로 설정한다.
5. 처음에는 PD를 중심으로 표시하고, 사용자가 선택한 설정값을 주요 화면에 추가한다.
6. 리모트와 IO-Link 제품이 가능한 한 같은 측정·상태·설정·출력 위젯을 공유한다.
7. 미수신·만료·해석 불가와 실제 정상·OFF를 구별한다.

## 5. 리모트 종류별 할당과 화면

다음 표는 기존 EXW1-BMTAC 매뉴얼 검토 기록을 요약했다. `*`는 모델 옵션 자리이며 주문 가능한 단일 품번이 아니다. 실제 모델·무선 버전·설정과 대조해야 한다.

| 종류 / 모델 패턴 | 입력 B | 출력 B | 표시·조작 방향 |
|---|---:|---:|---|
| 디지털 입력 e-CON / EXW1-RDX*E4** | 2 | 0 | 16점 입력을 8비트씩 그룹화 |
| 디지털 출력 e-CON / EXW1-RDY*E4** | 0 | 2 | 16점 출력 조회·강제 ON/OFF·순차 시험 |
| 디지털 입출력 e-CON / EXW1-RDM*E3** | 2 | 2 | 각 방향 하위 8비트 유효, 할당 2B 유지 |
| 디지털 입력 그로밋 / EXW1-RDX*G4C* | 2 또는 4 | 0 | 입력과 선택적 알림 영역 구분 |
| 디지털 출력 그로밋 / EXW1-RDY*G4C* | 0 | 2 | 출력 공용 패널 |
| 디지털 입출력 그로밋 / EXW1-RDM*G3C* | 2 또는 4 | 2 | 8점 입출력 및 선택적 알림 |
| 밸브 매니폴드 / EXW1-RDY*M5C* | 0 | 4 | 32점 출력 접점 확인 |
| 아날로그 입력 / EXW1-RAXZA2C | 8 | 0 | 4채널, 채널별 2B 원시값 |
| IO-Link Class A / EXW1-RLAPA8C, V2.0 | 2–130 | 2–130 | 최대 4논리 포트, 고정부 2B 포함 |
| IO-Link Class B / EXW1-RLBPA7C, V2.0 | 2–66 | 2–66 | 2포트, 고정부 2B 포함 |
| 위 IO-Link 모델의 V1.0 | 16 | 16 | 고정부 2B + PD 영역 14B |
| 참고: AMS / EXA1-**-SA-*L | 36 | 18 | 같은 베이스에 구성 가능한 별도 계열 |

아날로그 리모트의 전압·전류 모드 설정과 물리 단위 변환은 해당 리모트 전용 매뉴얼 맵으로 검토해야 한다. IO-Link 디바이스용 IODD를 그대로 적용하는 대상으로 가정하지 않는다.

## 6. 바이트 맵 검수에서 중요한 사항

```text
채널 입력 시작 = 베이스 진단 길이 + 앞 등록 채널들의 입력 할당 합
채널 출력 시작 = 앞 등록 채널들의 출력 할당 합
IO-Link 포트 시작 = 채널 시작 + 고정부 2B + 앞 포트들의 해당 방향 할당 합
```

- 입력과 출력의 위치 및 길이는 각각 계산한다.
- 통신이 끊겨도 등록된 채널의 할당은 유지한다.
- PFUW의 실제 PD가 8B이고 포트가 16B로 할당되었다면, 다음 포트 위치는 16B 뒤다.
- **4포트 × 16B와 고정부 2B를 같은 영역에 포함하면 전체는 66B다.** “전체 64B”가 고정부 포함인지 PD 영역만 뜻하는지 Configurator와 실제 맵으로 대조해야 한다. 고정된 기본값으로 추정하면 안 된다.
- 기존 검토에서 Modbus 입력 영역 시작은 레지스터 2048, 출력 영역 시작은 0이다. 바이트 오프셋과 16비트 레지스터 주소를 구별한다.
- 베이스 진단 영역과 Byte Swap 설정도 주소·비트 해석에 영향을 준다.
- Class A의 물리 커넥터와 논리 P1–P4 대응을 구분한다. Class B에 P3/P4를 표시하지 않는다.

## 7. PD 갱신 및 상태 표현

- 기본 PD 갱신은 **이전 요청 처리 완료 후 약 1초를 기다리는 방식**이다. 통신 시간을 포함한 엄밀한 1초 주기를 보장하지 않는다.
- 사용자 선택 ISDU 항목은 PD 연결 중 첫 수신 후 및 약 30초 간격으로 순차 조회한다. 설정 조회 시간이 길면 다음 PD 조회도 늦어질 수 있다.
- 선택한 단위·레이아웃 조건은 관련 ISDU 값과 검토된 규칙을 바탕으로 해석한다. 확인되지 않은 단위·배율을 임의 적용하지 않는다.
- 같은 값을 반복 수신할 때 화면 전체를 다시 만들거나 점멸시키지 않도록 DOM 재사용과 변화 강조를 적용했다.
- 미수신·오류·만료 시 이전 강조와 추이를 정리한다. 데이터 수신 성공과 제품 자체 정상 판단을 구별한다.
- 전체 현황의 상태는 등록 구성과 해당 세션의 조회 이력에 기반한다. 등록만으로 온라인 상태를 표시해서는 안 된다.

## 8. ISDU 조회·설정 편집

초기 화면은 PD 중심이며 설정값은 사용자가 선택하여 밖으로 꺼낸다. 선택은 채널·포트·IODD 정의별로 유지하고 별도 설정 화면과 동기화한다.

239개 정의에서 읽기 가능한 13,288개 바인딩을 대상으로 공용 조회 처리를 검사한 기록이 있다. 이것은 13,288개 항목을 실물 장비에서 읽었다는 뜻이 아니다.

설정 쓰기는 지원되는 정수·코드 항목을 중심으로 범위를 검사하고, 항목마다 순차 전송 후 다시 읽어 확인한다. String/Float/복합 전체 쓰기와 명령형 WO 실행은 현재 일괄 편집 완료 범위에 포함하지 않는다. 여러 항목 중간에 실패할 수 있으므로 부분 성공을 사용자에게 명확히 보여주는지 검수가 필요하다.

초기 문서에는 EXW1-RL 매뉴얼의 DeviceRead/DeviceWrite 코드 충돌로 전송 연결을 보류한 기록이 있다. 이후 현재 로컬 구현에는 BMTAC 문서를 근거로 한 전송 경로가 추가되어 있다. 검수자는 오래된 보류 기록과 최신 구현을 구별하고, 실제 베이스·펌웨어의 요청/응답을 확인해야 한다.

## 9. 출력 및 시험 모드

- 디지털 출력, 밸브 출력, IO-Link PD OUT를 가능한 공용 조작 체계에 연결했다.
- 일반 접점은 ON/OFF, PD OUT는 정의에 맞는 Boolean·정수·고정 길이 HEX를 지원한다. 임의 HEX 비트를 밸브 접점으로 추정하지 않는다.
- 조회 → 대상 확인 → 조작 허용 → 쓰기 → 재조회 순서를 사용한다.
- 순차 시험 중에는 수동 출력·ISDU 쓰기·구성 변경을 제한하는 절차가 있다.
- 시험 종료·중지 시 OFF 확인을 수행하며 확인이 실패하면 OFF 미확인 상태를 표시한다.
- 출력 메모리 재조회 성공은 밸브 위치, 압력 변화 또는 실제 부하 동작을 확인한 것이 아니다.

42개 IODD 정의에 PD OUT가 있다는 분석 기록이 있다. 모든 출력 제품이 일반 접점 ON/OFF와 같은 방식으로 동작한다는 뜻은 아니다. 액추에이터·압력 제어 등 명령 시퀀스가 있는 제품은 전용 제약 검토가 필요하다.

새로운 IODD도 같은 파이프라인을 활용할 수 있으나 업로드만으로 단위·배율·조건·출력·진단의 정확성을 보장하지 않는다. 향후 AI 분석·검토 보조와 승인된 제품 정의 관리가 필요하다.

## 11. 제품 이미지·선화와 디자인

제공된 대표 CAD를 베이스·리모트·포트 제품에 연결하고 회전·확대·선택 표시를 구현했다. EXW1-BMTAC, EXW1-RLAPA8C, PFUW760-L1의 원본·표시용 모델 관리 기록이 있으며 PF3A 계열 추가 자산 작업도 존재한다. 보유 외형과 실제 지정 품번의 대응은 자산 목록과 함께 검수해야 한다.

사용자가 선택한 방향은 **선화와 부분 강조**, SMC 블루 중심의 공통 디자인이다. 현재 차콜 배경, 밝은 본문, 블루 주요 조작을 적용하고 CAD는 흰 표시 영역에 배치했다. 녹색은 실제 수신·ON, 황색은 경고, 적색은 오류 같은 의미에 사용한다.

현재 남은 문제는 제품 사이의 선화 품질·시점·크기 통일, 화면 밀도, 중첩 패널, 설정 화면의 일관성이다. 색상 변경만으로 해결되지 않는 정보 구조 문제가 있다.

## 12. 최근 합의한 UI 개선 방향 — 아직 제안 단계 포함

1. 첫 화면에서 연결된 채널·제품과 주요 값이 먼저 보이도록 한다.
2. 베이스·Modbus 연결 정보는 상단에 압축하고 바로 설정에 진입할 수 있게 한다.
3. IO-Link 채널에서는 각 논리 포트의 제품·주요 PD·선택 설정을 한눈에 보여준다.
4. 제품 선택 후 상세 측정·진단·설정·출력으로 들어가도 채널·포트 맥락을 유지한다.
5. 오류·미수신·만료처럼 조치가 필요한 위치를 쉽게 찾게 한다.
6. 같은 상태를 넣은 ‘제품 중심’과 ‘축약 구성도 중심’ 두 첫 화면 시안을 비교한다.
7. 구조를 선택한 뒤 공용 컴포넌트와 설정 화면까지 일괄 통일한다.

두 새 시안 비교와 이후 전면 적용은 이 문서에서 완료로 보고하지 않는다. Figma MCP는 시안·공용 컴포넌트 정리에 활용할 후보로 조사했으며 설치·연결 완료가 확인된 상태는 아니다.

## 13. 검증 기록과 실기 확인 경계

최근 구현 기록에는 다음 검증의 통과가 남아 있다.

- 전체 탐색, 239개 정의·432개 레이아웃 연결, 채널·포트별 선택 유지
- 사용자 설정 선택, 읽기, 입력 범위 거부, 모의 순차 쓰기 및 재조회
- 디지털 바이트 그룹·ON 강조, 아날로그 원시 표시, 미수신·실패·만료
- 출력 조회·허용·쓰기·중지 및 모의 충돌 처리
- 제품 모델 로딩·포트 선택·시점 유지
- 데스크톱·모바일 가로 넘침, 반복 갱신 무점멸, 동작 줄이기 설정

브라우저 검증은 장비 요청을 차단하거나 모의 응답으로 처리했다. 이러한 통과 기록을 실제 장비 동작 검증으로 확대하면 안 된다.

초기 대화에는 사용자가 PFUW 연결, 포트 이동 및 FIXED/ERROR 비트 반영을 확인한 기록이 있다. 그러나 전체 제품·최신 변경의 실기 시험 성적서는 아니다. 2026-10-01 작업 기록에는 대상 TCP 연결 시간 초과와 실제 읽기 실패가 남아 있다. 따라서 현재 연결 성공 여부를 이전 대화만으로 판정하지 않는다.
