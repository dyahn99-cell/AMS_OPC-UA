# 최신 현황

현재 PD 진단 172개, 비주기 응답/위젯 16개, 문서 충돌 보류 51개. [상세 현황](DIAGNOSTIC_STATUS.md) 참조. 아래는 단계별 구현 이력이다.

# PD 해석 1단계: 모의 입력 이미지

실제 통신을 연결하지 않은 순수 JS 해석기와 모의 HEX 입력 화면을 추가했다.
마스터 편집 아래 「모의 PD 패킷 검증」에서 구성한 마스터 입력 이미지 전체를 입력한다.
포트별 결과 버튼을 누르면 그 포트의 PD 결과를 공용 위젯에 전달한다.
PD OUT 및 ACYCLIC은 이 패킷에서 갱신하지 않는다. 패킷 시험과 수동 모의 값은 별도 컨텍스트다.

## 입력 계약

입력은 마스터 한 대의 순서가 확정된 바이트 배열이다. Modbus word 배열이 아니다.
전체 입력 할당과 정확히 같은 길이, 0–255 정수, 연결 상태와 수신 시각을 요구한다.
베이스 레지스터 위치·레지스터 바이트 순서·실제 통신은 이번 단계 범위 밖이다.

매뉴얼 OM_EXW1-RL_DOC1046608EN-4 PDF 142,155–162쪽에 따라:
고정 2-byte 상태 영역 뒤에 포트별 입력 할당을 분리한다.
DevCom=0, PQ=0, 전송 끊김, 30초 초과 패킷은 측정값을 무효화한다.
DevErr는 Warning 또는 Error를 포함하므로 이번 구현에서는 보수적으로 수치를 보류한다.
16/32-bit 및 전체 byte swap을 포트 할당 영역에 적용한다. 2-byte mapping의 Swap32는 무교환이다.
정렬되지 않은 swap 크기 또는 복원 후 0이 아닌 여유 패딩은 mapping_unconfirmed로 보류한다.

IODD의 명시 bitOffset와 IntegerT/UIntegerT/BooleanT를 해석한다.
안전 정수 범위를 넘는 수치, 복합/배열/문자/float, 주소 미확인은 정상 수치로 반환하지 않는다.
별도 코드와 정의 범위 밖 값도 정상값으로 전달하지 않는다.
공학 단위 변환은 기존 SHA/항목 규칙과 별도로 확인한 V_Unit을 모두 요구한다.
조건부 PD 레이아웃의 선택은 수동 구성이며 장비와 일치하는지는 아직 검증하지 않았다.

## 제품 진단 적용 범위

정확한 IODD SHA로 ISE70 오류 bit2, PF3W704-LT-X445 오류/범위 bit8/9/10을 연결했다.
해당 플래그가 켜지면 수치를 보류하고 상태 비트는 계속 표시한다.
현재 PF3W에서는 공통 오류는 양쪽, 유량/온도 범위 이상은 해당 수치만 보류한다.
그 외 정의는 원시값을 추출해도 diagnostics_unverified로 수치 전달을 보류한다.
따라서 전체 제품의 진단까지 완성된 해석기라고 볼 수 없다.

## 검증 예제

ISE70 MPa, PD 3E 80: raw 2000 → 0.25 MPa.
PF3W704-LT-X445, PD 02 EE FF CE 00 00: 유량 raw750 → 3 L/min, 온도 raw-50 → -5°C.
두 포트를 함께 할당해 값 분리와 한쪽 PQ 무효가 다른 포트에 영향을 주지 않는지 검사한다.
공식 8-byte/7-byte+padding swap 예제, 미래/오래된 시각, 잘린/긴 패킷,
특수 코드, 진단 플래그, 미확인 제품의 수치 차단을 검사한다.

다음 단계는 나머지 제품의 진단 조건을 확장하고, 베이스 입력 레지스터를 이 바이트 입력 계약으로
전달하는 읽기 어댑터를 검증하는 것이다. 서버 시작/재시작 및 실제 장비 접근은 수행하지 않았다.


## 2단계 반영: 진단 확장 및 읽기 어댑터 계약

앞의 두 정의 한정 진단은 37개 정의/155개 레이아웃으로 확장했다.
압력 계열 ISE70/71, ISE7xG, ISE79S, ZSE/ISE20B/C 및 PF3W의 근거는
outputs/iodd/diagnostic-profiles.json에 정확한 SHA, 비트, 공식 PDF와 페이지로 남겼다.
해당 문서의 근거를 가진 기존 변환 규칙에서 대상을 선정하고 모든 레이아웃의 비트/Boolean 이름을 재검사했다.
이 단계 당시 남았던 202개 정의의 최신 분류는 아래 3단계와 diagnostic-review.json을 참조한다.

추가 발견: 압력 계열의 F_0/V_diAG는 OFF/ALL/PrES 선택형이고 구형 PF3W도 진단 OFF가 가능하다.
오류 비트 0만으로 정상값을 허용하던 부분을 수정했다. 이제 해당 정의는 V_diAG=1을
명시적으로 확인해야 수치를 전달한다. 모의 패킷 화면에서 이를 별도 체크하며 자동 확인하지 않는다.
현재형 PF3W는 PDF 72쪽의 고정 진단 비트 15/8/9를 적용한다.
모든 등록 프로파일에 대해 모든 진단 비트를 개별 ON 하여 수치 보류를 검사했다.

assets/iodd-register-input.js는 read 함수를 주입받는 어댑터다.
실제 주소는 추정하지 않고 mapping.confirmed, 베이스/채널, FC3 또는 FC4,
시작 레지스터, high-low/low-high, 첫 바이트 오프셋을 명시해야 한다.
응답의 베이스/채널/기능/주소·워드 개수와 범위를 검사한 후 마스터 입력 이미지로 바꾼다.
읽기 동안 구성 변경은 응답 경로를 바꾸지 않는다. 타임아웃/응답 불일치는 연결 끊김으로 반환한다.
테스트 주소 100은 합성 예제이며 SMC의 실제 주소로 제시한 것이 아니다.
이는 실제 Modbus 수집 서비스가 아니며 아직 운영 수집 루프에 연결하지 않았다.

검증: check_iodd_diagnostics.cjs, check_iodd_register_input.cjs, check_iodd_pd.cjs 통과.
실제 장비 접속, 자동 폴링, 출력 쓰기, 서버 재시작은 수행하지 않았다.

## 3단계: 전체 239개 정의 진단 분류

2026-09-29: 기존 37개에서 82개를 추가하여 119개 정의 / 237개 레이아웃에 PD 원시 측정값 진단을 적용했다.
추가 대상은 D-MH2, 일반 PF2M, 현행 PF3A, PFCA, PFUW, FC3W, PSE202A다.
PFCA/PFUW의 누적값과 유량, PF3W의 온도와 유량, PSE202A의 채널별 범위 진단은 해당 필드만 차단한다.
FC3W 밸브 위치는 원점 검출 비트가 1일 때만 허용한다. 공통 오류는 관련 측정값 전체를 차단한다.
상태 비트는 계속 표시한다. 진단 근거가 없는 숫자 필드는 보류한다.

전체 분류: PD 적용 119, 비주기 조회 필요 16, 문서·IODD 충돌 50, 추가 근거 필요 54.
정확한 정의 SHA별 사유·문서·페이지·필요 조회 주소는 diagnostic-review.json 및 diagnostic-review.md에 기록했다.
비주기 조회 목록은 요구사항이며 실행된 읽기나 구현 완료 표시가 아니다.
특수 X731 및 과거 개정은 현행 일반 제품의 근거를 자동 상속하지 않는다.
PF2MC 고정출력 비트, PSE54/57·PSH의 누락 비트 등은 해결 전 측정값 전달을 보류한다.

검증: 모든 등록 레이아웃의 정상 입력, 각 오류 비트, 원점 미검출, 영향받지 않는 다른 측정값,
필수 진단 설정 누락 및 전체 239개 분류의 누락/중복 여부를 자동 검사했다.

이는 원시 진단 적용 범위다. 공학 단위 선택·복합 타입·비주기 통신·실기 검증의 완료를 의미하지 않는다.
