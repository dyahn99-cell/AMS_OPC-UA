# 장비 구성 화면 통합

운영 대시보드의 「장비 구성 · IO-Link」 링크는 /device-workspace를 연다.
기존 서버가 실행 중이면 새 코드는 다음 앱 실행부터 반영된다. 이번 작업에서는 서버를 재시작하지 않았다.

## 구현

- GET/PUT /api/device-workspace: 여러 베이스/채널의 마스터 구성 저장.
- 별도 device_workspace.sqlite3에 트랜잭션 저장. 운영 config/nodes 파일과 통신 워커를 변경하지 않는다.
- 저장 버전 비교로 오래된 화면의 덮어쓰기를 409로 차단한다.
- 동일 베이스/채널, 제품 SHA/레이아웃, 포트 모드/길이/합계 등을 서버에서 재검증한다.
- 기존 LocalAccessMiddleware의 로컬 세션 토큰 및 동일 출처 보호를 그대로 적용한다.
- 서버 트리: 베이스 → 채널/마스터 → 사용 포트/제품. 포트 클릭은 정확한 IODD 정의를 연다.
- 브라우저의 모의 값은 마스터 ID/베이스/채널/포트/정의/레이아웃/PD 구성별로 분리한다.
- 모의 값은 30초 경과 시 미수신으로 표시하고 선택 포트 연결 끊기는 해당 포트만 무효화한다.

## 저장 흐름

서버에서 불러오기 → 새 마스터 구성 또는 기존 마스터 선택 → 아래 편집기 수정 →
「편집 구성을 서버에 저장」. 기존 「이 브라우저에 저장」은 별도의 로컬 초안 기능이다.
서버 저장 충돌 시 편집 내용은 유지되며 서버에서 다시 불러와 재검토한다.
현재 운영 EXA1/Remote I/O 트리를 자동 병합하지 않는다. 신규 구성 트리는 IO-Link 계획 전용이다.
PD/비주기 실제 읽기·쓰기, 실제 통신 끊김 판정, 장비 자동 검색은 아직 연결하지 않았다.

## 검증

파서/분류/저장소 테스트 7개 통과. 모든 432개 레이아웃의 서버 할당 검증과
길이 부족 거부, DB 재열기/버전 충돌/채널 중복 검사를 포함한다.
장비 런타임을 import하지 않는 FastAPI ASGI 테스트에서 페이지, 인증된 API,
저장/복원, 409, 422, 413, 교차 출처 403을 검증했다. 실제 소켓/서버를 시작하지 않았다.
모의 값의 마스터/포트/버전 분리, 오래된 값, 선택 포트 연결 끊기 검사 통과.
브라우저 육안 검증과 앱 전체 회귀검사, 실물 통신 검증은 별도다.

빌드: python tools/iodd/build_all_widgets.py
생성 파일: assets/iodd-workspace.html, assets/iodd-layouts.json 및 기존 오프라인 HTML.
기존 PyInstaller spec은 assets 전체를 포함한다. 패키징 실행 자체는 검증하지 않았다.
