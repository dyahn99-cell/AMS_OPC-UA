# EXW1 / IO-Link 기능 구현 상태

현재 화면: http://127.0.0.1:8011/ · 장비 대상: 192.168.0.10:502, Modbus TCP Unit 1.

## 연결한 기능

- 수동 등록한 CH1–15 리모트의 **할당 바이트**를 합산해 입력·출력 시작 위치 계산. 통신 끊김으로 등록 위치를 당기지 않음.
- IO-Link 각 포트의 IODD 버전·레이아웃·바이트 순서·모니터 사용 여부·입출력 할당을 개별 저장.
- PD 입력은 응답 완료 후 1초 갱신. ON 진단의 윤곽선, 바이트별 비트 분석, 일반 입력의 DOM 유지, 수신 추이(최근 60회).
- 239 IODD 정의 / 215 제품의 공용 표시 구성과 제품별 고정 ISDU 항목. 별도 설정 페이지에서 정수·코드 설정을 일괄 검증하고 순차 적용·재조회.
- 검토된 배율 326개 / 129 정의: 실제 ISDU 단위 설정 및 레이아웃 조건을 조회하여 적용. 단위·조건 조회는 30초 캐시, 제품·포트·설정 변경 시 무효화. 규칙 없는 측정값은 raw로 표시.
- 일반 RDY/RDM/밸브와 IO-Link PD OUT를 동일 출력 패널에서 조회·쓰기. 출력 보유 42 정의에 Boolean/정수/고정 길이 HEX 필드 전송 지원. HEX 내부 비트 의미를 임의로 디지털 접점에 대응하지 않음.
- 출력의 실제 리모트 ID·주소·할당을 구성표와 대조. IO-Link 포트는 고정된 Unit 번호를 추정하지 않고 실제 Unit ID 0054–0057로 찾음. 쓰기 전에 포트 통신/PQ 확인. 이전 조회값 비교, 선택 필드 마스크, 다른 비트·헤더·여유 바이트 보존, 적용 후 재조회.
- 선택한 디지털 접점 1–32개를 서버에서 **한 번** ON→OFF 순회. 간격 200–5,000ms. 초기 선택 접점은 OFF여야 함. 중지하면 현재 접점의 OFF를 마무리. ON 재전송 없음. 통신 실패 시 확인된 이미지에 한해 OFF 정리하며, 확인 불가능하면 `OFF 미확인` 표시.
- 테스트 중 수동 출력·ISDU 쓰기 및 화면 구성 변경 제한. 새로고침 후 서버 테스트의 중지·상태 확인 복원.

## 남은 실장비 확인과 기능 범위

- 2026-10-01 작업 중 실제 `/read` 요청은 장비 응답을 얻지 못하고 503으로 끝남. 확인 시 PC에 192.168.0.x 주소의 인터페이스가 없었고 192.168.0.10:502 TCP 연결도 시간 초과. 이번 변경에서 실제 출력·설정값은 쓰지 않았음. PC를 장비 네트워크에 재연결한 후 PD/ISDU, 실제 출력 장치의 쓰기·OFF·중지 확인 필요.
- 출력 표시/재조회는 **출력 메모리 확인**이다. 밸브 위치나 부하 동작의 피드백을 의미하지 않는다. PLC의 동시 쓰기는 조회값 충돌/재조회 불일치로 표시할 수 있다.
- 마스터 할당 입력은 대시보드의 읽기/쓰기 맵 구성이다. 장비 자체의 포트 할당을 원격 변경하는 기능은 아니다.
- 일반 RAX 아날로그 입력은 4채널 원시 바이트 표시. 전압/전류 모드 및 실제 단위 변환은 별도 매뉴얼 맵 연결 대상이다.
- String/Float/복합 전체 ISDU 쓰기와 명령형 WO 실행은 현재 설정 일괄 적용 대상에 포함하지 않는다.
- 최종 디자인, 새로운 IODD의 AI 검토, 127채널 화면 확장은 별도 단계이다.


## 제품 이미지·3D (2026-10-01)

제공된 GLB 3개(EXW1-BMTAC, EXW1-RLAPA8C, PFUW760-L1)를 베이스·채널·포트 화면에 연결했다. 채널 구성표의 RLA 사진 버튼은 해당 채널로 이동한다. PFUW760-L1 계열 IODD에는 대표 외형을 표시한다. 미제공 모델은 임의의 다른 제품 3D로 대체하지 않는다.

- 회전/확대, 기본 시점, 자동 회전, 전체 화면 지원. 입력 갱신·논리 포트 선택 시 동일 리모트의 3D 시점을 유지한다.
- PORT1(P1/Pin4, P3/Pin2)·PORT2(P2/Pin4, P4/Pin2)의 3D 마커를 선택하면 논리 포트를 고른다. DOC1046608-4 인쇄 p12–15 대조, 마커 좌표는 CAD 외형 기준 수동 지정. 원본에 개별 포트 노드가 있다고 가정하지 않는다.
- 원본 GLB 3개는 제공 SHA256 그대로 보존한다. `.display.glb`에는 SMC 공식 제품 사진을 참고한 대표 배색을 적용했다. EXW1은 흰 본체·짙은 라벨 영역·금속 커넥터, RLA는 파란 하단 전면과 전원 커넥터, PFUW는 흰 본체·파란/검은 표시창·회색 버튼·케이블·금속 브래킷을 구분한다. 인쇄 문자/로고와 표시창 숫자는 재현하지 않는다. 실제 수신값과 통신 상태는 공용 위젯/포트 마커로 표시한다.
- `tools/iodd/prepare_product_models.py`는 재질별 표시 GLB를 재생성한다. CAD 면 ID와 좌표로 영역을 나누며 색 경계에서는 원래 삼각형의 평면 위에서 속성을 보간한다. 표면 위치·조립 노드/변환은 유지하고 별도 CAD 선을 제외한다. 원본 버퍼/속성/재질 보존, 면별 면적·면적 중심·방향 보존, 제품별 사용 색상 검증은 `test_product_models.py`.
- 원본·표시용 SHA256, sRGB 팔레트, 면별 색상 개수 및 참고 URL은 `assets/product-models/manifest.json`, `display-manifest.json`에 기록한다. 채널 구성표와 포트 화면의 정지 PNG도 배색한 모델로 갱신했다.
- 렌더러는 `assets/vendor/model-viewer`의 고정 4.3.1 버전이며 라이선스·출처도 저장했다. GLB·정지 이미지·렌더러를 전부 로컬 서버가 제공한다.
- `node scripts/check_iodd_product_models.cjs`: 세 모델 로딩, 포트 마커 선택, 카메라 유지, 채널/포트 분리, 상태 표시, 미등록 모델 처리 및 외부/장비 요청 없음 검증. 기존 입력·출력 브라우저 검증도 통과.

## CAD 형상 기반 선화 보기 (2026-10-12)

초기 단순 SVG 도식은 제거했다. 제공된 GLB의 실제 표면과 모서리 선 프리미티브를 그대로 사용하는 `.outline.glb`가 기본 화면이다. 원본 바이너리 버퍼·표면/선 위치·노드·조립 변환을 보존하고 밝은 불투명 면과 짙은 단색 선 재질로 표시한다. 면이 뒤쪽 선을 가리므로 투시 와이어프레임처럼 모든 선이 겹치지 않는다. 원본 선의 COLOR_0 및 법선 속성을 렌더링에서 제외해 색상 없이 균일하게 표시한다. 실제 CAD 커넥터·나사·브래킷의 형상을 유지하며 기본 선화도 회전/확대가 가능하다.

`tools/iodd/prepare_outline_models.py`로 세 모델을 재생성하고 `assets/product-models/outline-manifest.json`에 원본/선화 SHA256과 CAD 선 개수를 기록한다. 제품 배색 보기와 선화 보기는 동일 model-viewer에서 소스만 전환한다. 포트 마커는 실제 모델 좌표에 놓이며 선택은 파란 윤곽선, 수신 헤더의 통신은 초록색, 장치 오류는 주황색으로 강조한다. 미수신/만료 시 상태 강조를 지운다. 데이터 읽기·쓰기 요청 로직은 변경하지 않는다.

검증: `test_product_models.py`에서 원본과 선화의 바이너리/조립/표면 및 선 속성 보존을 확인한다. `node scripts/check_iodd_line_art.cjs`는 CAD 선화 로딩, 실제 포트 클릭/논리 선택, 상태 강조/해제 및 배색 전환을 검증한다. 장비 POST는 차단하며 강조 상태는 모의 입력으로만 검증한다.

## 사용자 선택 설정 위젯 (2026-10-12)

첫 사용 시 추천 설정을 자동 고정하지 않고 PD 측정값·상태만 기본 표시한다. 기존 사용자가 명시적으로 저장한 v1 고정 선택은 유지한다. 설정 선택은 제품별 하드코딩 목록 대신 IODD의 읽기 가능한 ACYCLIC 항목과 접근 가능한 Record 하위 항목에서 구성한다. 기존 검토된 제품 표시 이름은 사용할 수 있지만 선택 가능 여부를 제한하지 않는다. 읽기 전용·문자열·복합 항목도 조회 카드로 선택 가능하며 미해석 형식은 HEX로 표시한다. 설정 쓰기 범위는 기존 정수/코드 지원 범위를 유지한다.

설정 페이지의 별표 선택은 채널·포트·IODD SHA별로 즉시 저장하며 별도 탭과 메인 화면에 동기화한다. 선택 항목만 필터링/검색, 모두 표시 해제, 개별 설정 읽기가 가능하다. 메인 카드에서 상세 설정의 해당 항목으로 이동하거나 표시를 해제한다. 새로고침·포트 전환 후 선택이 유지되며 다른 포트·채널·제품에 전파되지 않는다. 표시 선택은 장비 쓰기를 발생시키지 않는다.

PD 연결 중 선택한 설정값은 첫 성공 수신 후, 이후 30초 간격으로 순차 ISDU 조회한다. PD 자체는 응답 완료 후 1초 갱신이다. 설정 묶음 조회 중에는 다음 PD 요청을 기다리므로 ISDU 항목/응답 시간이 많으면 PD 갱신 간격이 길어질 수 있다. 실제 시간은 각 카드에 표시한다. 설정값만 수동으로 읽을 수도 있다. 단위/레이아웃 확인용 기존 ISDU 조회는 고정 카드 수와 관계없이 PD 해석에 필요하다. 범위 밖 입력이면 쓰지 않고, 복수 설정 적용은 순차 전송·각 항목 재조회 검증 후 다음으로 진행한다. 원자적 일괄 쓰기는 아니다.

`node scripts/check_iodd_user_settings.cjs`: 239 IODD / 13,288 읽기 가능한 바인딩의 공용 해석, 초기 PD-only, 사용자 문자열/코드 고정, 저장·새로고침·포트 분리·여러 탭 동기화, 자동 조회, 항목 이동, 입력 범위 거부, 두 정수 설정의 순차 검증 쓰기, 표시 해제 검증. 장비 요청은 모두 모의 응답이며 실장비 검증을 의미하지 않는다. 기존 일반 리모트 PD 및 IO-Link/일반 출력 UI 회귀 검증도 통과했다.

## 워크스페이스 UI 정리 (2026-10-12)

기존 검증 화면의 DOM 기능 ID와 읽기/쓰기 API를 유지하면서 배치를 재구성했다. 왼쪽에는 등록 채널 탐색, 상단에는 제품·포트 선택과 연결/중지, 본문에는 CAD 선화와 측정값·사용자가 선택한 설정값을 둔다. 채널 등록표, 마스터 할당, 바이트 분석과 수신 상세는 기본 접힘 상태로 별도 구성/점검 영역에 배치한다. 설정 페이지도 공용 밝은 스타일을 사용하며 모바일에서는 표 내부 스크롤을 사용한다. 새로운 채널 버튼은 기존 채널 컨트롤러에 위임하고, 출력 테스트 중 기존 채널 잠금을 따른다. 색상은 선택/상태 표시를 중심으로 쓰며 네트워크 연결을 임의로 표시하지 않는다.

공용 CSS: `assets/iodd-ui.css`; 채널 탐색: `assets/iodd-ui.js`. `scripts/check_iodd_ui.cjs`에서 데스크톱/모바일 렌더링, 중복 카드 방지, 구성표 접힘/열기, 탐색 잠금, 설정 페이지 가로 넘침 및 오류 없음 확인. 기존 선택 설정·PD·출력/중지·3D/포트 회귀 검증은 장비 요청을 모의 응답 또는 차단으로 처리해 통과했다. 화면 구조를 정리한 단계이며 실장비 검증이나 최종 제품 UI 완성을 의미하지 않는다.

- 대표 지표는 현재값과 최근 60회 수신 추이·최소/최대/평균을 함께 표시합니다. 다른 측정값을 대표로 선택할 수 있으며 채널·포트·제품별로 저장됩니다.
- 그래프는 실제 수신 시각을 사용합니다. 5초 이상의 간격은 연결하지 않으며, 단위/배율 변경 및 미수신 전환 시 기록을 초기화합니다. 임계값 선이나 정상 범위는 추정하지 않습니다.
- 데이터 수신/장치 판단/최종 시각을 분리하고, 진단 ON 및 해석 보류를 정상 상태로 오인하지 않도록 표시합니다. ISDU 설정은 기존 사용자 선택 방식입니다.
- 채널 현황은 등록 구성과 해당 세션에서 조회한 입력 이력만 보여줍니다. 전체 채널 자동 폴링이나 연결 자동 탐지는 아닙니다.
- 품번 선택은 접힘 영역, 통신 원문은 구성·점검으로 이동했습니다. 입력 접점은 공용 상태 그리드, 출력은 기존 조회·조작 패널로 연결됩니다.
- check_iodd_operational_ui.cjs 검증: 대표값/추이/단위, 선택 유지, 연결 오류 및 그래프 초기화, 채널 탐색, 모바일. 실기기 요청은 모두 모의 응답 처리했습니다. operational-focus-mock.png는 모의 수신 화면임을 이미지에 표시합니다.
